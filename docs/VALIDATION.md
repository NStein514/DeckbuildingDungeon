## Reproduce

Standard Flutter machine:

```sh
bash tool/validate.sh
python3 -m http.server 8080 --directory build/web
```

The optional browser smoke script uses Playwright and an installed Chromium. From a second terminal:

```sh
npm install --prefix /tmp/deckbound-browser --cache /tmp/deckbound-npm playwright
dart run tool/smoke_checkpoints.dart /tmp/deckbound-checkpoints.json
CHECKPOINTS=/tmp/deckbound-checkpoints.json NODE_PATH=/tmp/deckbound-browser/node_modules node tool/browser_smoke.cjs
```

`CHROME_EXECUTABLE` and `BASE_URL` override its browser executable and target. It creates an isolated browser profile and writes screenshots to the system temporary directory under `deckbound-smoke`.

For this cloud machine, activate writable caches first:

```sh
export PATH="/workspace/toolchains/flutter/bin:$PATH"
export PUB_CACHE=/workspace/.pub-cache
export XDG_CONFIG_HOME=/workspace/.config
export ANALYZER_STATE_LOCATION_OVERRIDE=/workspace/.dartServer
export CI=true FLUTTER_SUPPRESS_ANALYTICS=true DART_SUPPRESS_ANALYTICS=true
cd /workspace/DeckbuildingDungeon
```

The reusable environment install/start instructions include these settings. Processes do not survive environment snapshots; start the server again in each task.

## Limits

Android/iOS app compilation, signing, physical-device/simulator behavior, and native plugin startup were not verified. Native file replacement was exercised on Linux using the same file-store implementation; this is not a mobile durability test. Windows/macOS native hosts are not generated. Browser tests cover Chromium only, not Safari/Firefox or installed/offline PWA behavior. The application needs no gameplay network service, but browser offline installation/caching is not implemented.

Run saves intentionally resume at encounter entry, not mid-turn. Browser storage can be cleared and is origin-specific; use one active game tab. Unsupported/corrupt saves remain intact and require deliberate external recovery; no destructive repair UI is provided. Starting-build unlocks, lifetime win/defeat totals, final artwork, and audio playback are deferred. Repeated descent scaling is provisional: the 100-descent test supplies simulated victory outcomes and verifies state/save invariants, not combat balance or viable survival at those depths. Large-text and comprehensive screen-reader/device testing remain polish work.
